## Ordered steps
1. Add a Mongo health check that runs a bounded ping against the configured database and maps connectivity errors to Degraded.
2. Register it separately from provider checks and map `/health/storage`.
3. Add sanitized information logging for successful upserts and remove normalized place identifiers from cache failure logs.
4. Extend tests for health status, fail-open writes and log redaction; keep existing persistence behavior unchanged.
5. Update architecture docs, run `scripts/check`, complete independent review, and attach acceptance evidence.

## Risks & open questions
- Mongo cache is intentionally optional, so returning `Degraded` keeps readiness information useful without failing recommendation traffic. Recommendation: retain this fail-open policy.
- A ping proves connectivity but not write permission. Recommendation: use sanitized upsert logs and the existing Mongo integration test for write verification rather than performing a mutating health probe.
